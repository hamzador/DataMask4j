PostgreSQL data masking with JDBC

Read-only preview

var report = new JdbcMasker(masker).dryRun(
    sourceDataSource,
    new JdbcTable("customer_db", "public", "customer")
);

The preview uses a read-only transaction and explicit schema checks. It returns counts without raw records. Only ordinary tables and text/varchar columns are supported.

Experimental export

var report = new JdbcExporter(masker).export(
    sourceDataSource,
    new JdbcTable("customer_db", "public", "customer"),
    testDataSource,
    new JdbcExportTarget(
        new JdbcTable("dm_test_customers", "public", "customer"),
        "dm_mask_writer")
);

The destination must be separately configured, empty and explicitly provisioned. Source permissions must be SELECT-only for the selected relation. The target role needs SELECT and INSERT but not ownership or broad write grants. A database name starting with dm_test_ is a guard, not proof of non-production.

Related tables

JdbcExporter.exportAll accepts up to 32 explicit parent-first steps. Use shared keys and scopes to preserve compatible pseudonymised identifiers. Validated immediate non-cascading target foreign keys within the plan are supported; cycles and deferred constraints are rejected. One target transaction commits all rows or rolls back pre-commit failures. Inspect the target before retrying an ambiguous commit failure.
