Java record masking and Spring integrations

Explicit record annotations

public record Customer(
    @Mask(strategy = HMAC, scope = "customer:v1") String id,
    @Mask(strategy = REDACT) String notes
) {}
var masker = new RecordMasker(secretKey);
Customer masked = masker.mask(original);

All components must be annotated, even KEEP fields. The API creates a new public flat record. Nested objects and mutable collections are not supported; accessors and constructors must be trusted.

Spring Boot

datamask4j:
  enabled: true
  key-required: true

The starter is disabled by default. Supply a MaskingKeyProvider bean providing a fresh key array. The starter validates the key and clears the temporary array after copying. No HTTP interception, database export or job starts automatically.

Spring Batch

.processor(new RecordMaskingItemProcessor<Customer>(masker))

Map and record processors throw a generic failure instead of returning raw input. A real H2 JDBC integration test verifies chunk rollback and restart in the tested configuration. Previously committed chunks remain committed. Writers, metadata, listeners and retry policies must be configured safely by the application.

Initial tested baselines: Java 21, Spring Boot 4.0.9 and Spring Batch 6.0.6. Visit the complete starter examples.
